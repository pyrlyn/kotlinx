# KotlinX memory manager (GC)

The memory manager is a separate, replaceable component. The runtime (`compiler/runtime/runtime.c`) and
the code generated by `newkotlinc` use only the interface in [`kxgc.h`](kxgc.h); one implementation is
linked into every program.

| `--gc=` | Implementation | Cycles | Notes |
|---|---|---|---|
| `default` | [`default/gc.c`](default/gc.c) | collected | Perceus-style RC + synchronous trial-deletion cycle collector over the tracing region (Bacon & Rajan). The previous built-in GC, unchanged. |
| `rc` | [`rc/gc.c`](rc/gc.c) | leak | Same RC and regions, no cycle collector. Baseline for the collector's cost. |
| `boehm` | [`boehm/gc.c`](boehm/gc.c) | collected | RC + [bdwgc](https://github.com/bdwgc/bdwgc) 8.2.12 (conservative mark-sweep) for unreachable cycles. bdwgc is installed by `mise install` (`conda:bdw-gc` in `mise.toml`). |

## Selecting an implementation

```sh
bin/newkotlinc --gc=boehm Main.kt -o main      # or: --gc boehm
NEWKOTLIN_GC=rc bin/newkotlinc Main.kt -o main  # default when --gc is absent
```

`newkotlinc` compiles `compiler/gc/<name>/gc.c` together with the runtime and the program in one
`clang -O3 -flto` invocation, so the default implementation is inlined exactly as before (no extra cost).
`NEWKOTLIN_GC_DIR` overrides the directory with implementations (default: `<runtime dir>/../gc`).

## Interface (`kxgc.h`)

- Objects: `rt_alloc` / `rt_free` (acyclic classes), `rt_alloc_trace` / `rt_free_trace` (possibly cyclic
  classes), `rt_cc_possible_root` (traced object decremented to a non-zero count), `rt_cc_dead`.
- Runtime storage that may hold references (ArrayList storage, HashMap values, arrays):
  `rt_gc_mem_alloc` / `calloc` / `realloc` / `free`, so a tracing collector sees every reference.
- `rt_gc_collect` (also at exit), `rt_gc_name`, `rt_gc_stats` (collections, reclaimed, total/max pause).
  `KX_GC_STATS=1 ./program` prints them to stderr at exit.
- Object layout shared with the code generator: header word (low 32 bits = count, bits 32-33 color,
  bit 34 buffered) and vtable `{rel, trav, relo, freemem, cyclic}`. Retain/release fast paths stay
  inlined in generated code; an implementation that never sets the buffered bit gets plain RC.

## Adding an implementation

Create `compiler/gc/<name>/gc.c` implementing every function in `kxgc.h` (`common/regions.inc` provides
the RC regions), a `caps` file (`cycles`, `precise`, `asan`: what the tests may expect) and, if it needs
extra clang flags, a `config.sh` that prints them. `compiler/gc/tests/run.sh` picks it up automatically.

## Tests

`compiler/gc/tests/run.sh` (part of `compiler/test.sh`): for every implementation, C unit tests of the
interface (`tests/unit/gc_unit.c`, -O1 and -O3) and the GC-agnostic Kotlin tests in `tests/kt`
(output; plus zero live objects with `--leak-check` for `precise` and an ASan build for `asan`).
Tests marked `// gc-needs: cycles` are skipped for implementations that do not reclaim cycles.
`GCS="default boehm" compiler/gc/tests/run.sh` limits the set.

Benchmarks comparing implementations: [`bench/gc`](../../bench/gc/README.md).
