# KotlinX memory manager (GC)

Standalone home of the [KotlinX](https://github.com/pyrlyn/kotlinx) garbage collectors, their tests and
benchmarks. Extracted from `pyrlyn/kotlinx` at `9d9c1af` (`compiler/gc/` -> repository root,
`bench/gc/` -> [`bench/`](bench/)) following [`docs/extraction-plan.md`](docs/extraction-plan.md).

## How KotlinX uses this repository

- KotlinX pins an exact commit of this repository as a git submodule at `compiler/gc`, so the default
  `NEWKOTLIN_GC_DIR` (`<runtime dir>/../gc`) points at it and nothing else changes for the compiler.
  `bench/gc` in KotlinX is a symlink to `compiler/gc/bench`.
- The only contract is [`kxgc.h`](kxgc.h). It defines `KXGC_API_VERSION`; KotlinX checks it at compile
  time. Any change to a signature or to the object layout is a breaking change: bump the version and
  update KotlinX in the same pin-bump PR.
- Collectors stay single-file C translation units (`<name>/gc.c`), compiled by `newkotlinc` together with
  the runtime and the program (`clang -O3 -flto`). No prebuilt library.

## Working on the GC

The tests and benchmarks need a KotlinX checkout (runtime sources and a `newkotlinc` build). Work inside
KotlinX's submodule:

```
git clone --recurse-submodules https://github.com/pyrlyn/kotlinx && cd kotlinx/compiler && ./build.sh
cd gc/tests/zig && zig build gc        # full Zig GC suite (see tests/zig/README.md)
cd ../../bench/zig && zig build test   # Zig regression benchmarks against baselines.zon
```

To release a GC change: merge it here, then open a KotlinX PR that bumps the `compiler/gc` submodule and
runs `compiler/test.sh` plus the GC benchmarks.

## Overview

The memory manager is a separate, replaceable component. The runtime (`compiler/runtime/runtime.c`) and
the code generated by `newkotlinc` use only the interface in [`kxgc.h`](kxgc.h); one implementation is
linked into every program.

| `--gc=` | Implementation | Cycles | Notes |
|---|---|---|---|
| `perceus` | [`perceus/gc.c`](perceus/gc.c) | collected | Perceus-style RC + synchronous trial-deletion cycle collector over the tracing region (Bacon & Rajan). The original built-in GC, unchanged; it was named `default` until epoch became the default. |
| `incremental` | [`incremental/gc.c`](incremental/gc.c) | collected | `perceus` with the root buffer processed in slices of 64 under a per-step time budget (`KX_GC_BUDGET_US`, default 500 us); falls back to one pass when a single slice already exceeds the budget. |
| `epoch` | [`epoch/gc.c`](epoch/gc.c) | collected | **Default** (also `--gc=default`). Deferred RC for possibly cyclic objects: the program logs reference operations per epoch, a background thread applies them and runs concurrent cycle detection with Delta/Sigma validation. See [`docs/architecture.md`](docs/architecture.md#7-epoch-collector-deferred-rc-background-cycle-collection). |
| `rc` | [`rc/gc.c`](rc/gc.c) | leak | Same RC and regions, no cycle collector. Baseline for the collector's cost. |

Full description (object layout, RC + Perceus, regions, cycle collector, ownership rules):
[`docs/architecture.md`](docs/architecture.md).

## Layout

| path | contents |
|---|---|
| `kxgc.h` | the interface between generated code, runtime and implementation |
| `common/regions.inc` | RC and tracing regions, `rt_gc_mem_*` (RC implementations) |
| `common/object.inc` | header/vtable accessors, colors, pointer stack |
| `common/trial_deletion.inc` | MarkGray / Scan / CollectWhite passes and the adaptive threshold |
| `<name>/gc.c`, `<name>/caps`, `<name>/config.sh` | one implementation |
| `tests/` | unit and Kotlin tests for every implementation |
| `docs/` | architecture, plans |

## Environment variables

| variable | when | effect |
|---|---|---|
| `NEWKOTLIN_GC` | compile | default for `--gc` (unset: `epoch`) |
| `NEWKOTLIN_GC_DIR` | compile | directory with implementations |
| `KX_GC_STATS=1` | run | print GC statistics to stderr at exit |
| `KX_GC_BUDGET_US` | run | per-step budget of `incremental` (default 500) |
| `KX_GC_FREE_BUDGET_US` | run | `epoch`: freeing budget per epoch boundary (default half of `KX_GC_TARGET_PAUSE_US`, i.e. 1500) |
| `KX_GC_THREADS` | run | `epoch`: collector threads (default min(cores, 4)) |
| `KX_GC_MAX_QUEUED` | run | `epoch`: logs the collector may lag before the program waits (default: adaptive, 2-16) |
| `KX_GC_EXIT_DRAIN` | run | `epoch`: `1` drains the queue at exit in any build |

## Selecting an implementation

```sh
bin/newkotlinc --gc=perceus Main.kt -o main    # or: --gc perceus
NEWKOTLIN_GC=rc bin/newkotlinc Main.kt -o main  # default when --gc is absent
bin/newkotlinc Main.kt -o main                 # epoch (no --gc, no NEWKOTLIN_GC)
bin/newkotlinc --gc=perceus Main.kt -o main    # the pre-epoch default collector
```

The default is `DEFAULT_GC` in `compiler/src/driver/Main.kt` (`epoch`). `--gc=default` / `NEWKOTLIN_GC=default`
resolve to it. The old default collector is `perceus` (renamed from `default`; result files in `bench/results`
recorded before the rename label it `default`).

`newkotlinc` compiles `compiler/gc/<name>/gc.c` together with the runtime and the program in one
`clang -O3 -flto` invocation, so the default implementation is inlined exactly as before (no extra cost).
`NEWKOTLIN_GC_DIR` overrides the directory with implementations (default: `<runtime dir>/../gc`).

## Interface (`kxgc.h`)

- Objects: `rt_alloc` / `rt_free` (acyclic classes), `rt_alloc_trace` / `rt_free_trace` (possibly cyclic
  classes), `rt_cc_possible_root` (traced object decremented to a non-zero count), `rt_cc_dead`.
- Runtime storage that may hold references (ArrayList storage, HashMap values, arrays):
  `rt_gc_mem_alloc` / `calloc` / `realloc` / `free`, so a tracing collector sees every reference.
- `rt_gc_collect` (also at exit), `rt_gc_name`, `rt_gc_stats` (collections, reclaimed, total/max pause).
  `KX_GC_STATS=1 ./program` prints them to stderr at exit.
- Object layout shared with the code generator: header word (low 32 bits = count, bits 32-33 color,
  bit 34 buffered) and vtable `{rel, trav, relo, freemem, cyclic}`. Retain/release fast paths stay
  inlined in generated code; an implementation that never sets the buffered bit gets plain RC.

## Adding an implementation

Create `compiler/gc/<name>/gc.c` implementing every function in `kxgc.h` (`common/regions.inc` provides
the RC regions, `common/object.inc` + `common/trial_deletion.inc` the cycle collector passes), a `caps` file (`cycles`, `precise`, `asan`: what the tests may expect) and, if it needs
extra clang flags, a `config.sh` that prints them. `compiler/gc/tests/run.sh` picks it up automatically.

## Tests

`compiler/gc/tests/run.sh` (part of `compiler/test.sh`): for every implementation, C unit tests of the
interface (`tests/unit/gc_unit.c`, -O1 and -O3) and the GC-agnostic Kotlin tests in `tests/kt`
(output; plus zero live objects with `--leak-check` for `precise` and an ASan build for `asan`).
Tests marked `// gc-needs: cycles` are skipped for implementations that do not reclaim cycles.
`GCS="perceus rc" compiler/gc/tests/run.sh` limits the set.

**All new GC tests are written in Zig** in [`tests/zig`](tests/zig/README.md): a 1:1 port of `run.sh`
(`zig build ported`, verified against it by `compare.sh`), new unit tests of the C interface
(`zig build gc`), coverage (`zig build coverage`) and source-level mutation testing (`tests/zig/mutation`).

Benchmarks comparing implementations: [`bench/gc`](../../bench/gc/README.md).
