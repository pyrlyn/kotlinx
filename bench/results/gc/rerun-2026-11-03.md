# GC re-run 2026-11-03: default, incremental, epoch, boehm

Commit `1b07625` (origin/main), Apple M3 Max, same workloads for all GCs, interleaved runs.
Commands: `bench/gc/micro.sh default incremental epoch boehm` (11:31-12:26 EET) and
`bench/gc/compare.sh default incremental epoch boehm` (ROUNDS=3, median per case, 12:26-12:31 EET).
Per-benchmark records: `bench/results/gc-micro/*.json`, `bench/results/gc-nk/*.json`; tables: `micro-table.md`, `nk-table.md`.

Machine load (1-min average, sampled every minute): 4.5-13 during micro, 7.7 at suite start and 22.6 at suite end
(another worker's upstream test runs). Treat differences under ~10% as noise; suite `lru` is the most load-sensitive case.

## Changes vs previous results (Oct 29-31)

- micro, boehm: first run of big_live_churn, huge_live_churn, wide_graph_churn; other cases within 1-2% of Oct 31.
- micro, epoch: big/huge live churn 7-13% faster, wide_graph_churn 12% slower, peak RSS on huge_live_churn 934 -> 691 MiB.
- suite: boehm bigheap 1163 -> 1443 ms and lru 154 -> 266 ms, incremental lru 102 -> 880 ms, epoch lru 302 -> 403 ms
  were measured under the load spike at the end of the run; the remaining cases are within noise of Oct 31.

## Epoch vs Boehm

- Epoch wins: allocation (alloc_throughput 81 vs 180 ms, short_lived 78 vs 134), every large live heap case
  (big/huge/wide live churn 1.8-2.1x faster, max pause 9/29/166 vs 207/1009/2457 ms, peak RSS 2.4-2.7x lower),
  suite alloc, bigheap (86 vs 1443), free, trees.
- Boehm wins: cyclic garbage (epoch 157 vs 300 ms time, but epoch peak RSS 22.6 vs 3.4 MiB, max pause 1.5 vs 0.12 ms),
  suite lru (266 vs 403), fewer collections on big heaps.
- Default beats both on cyclic garbage and suite cycles/lru; compute-bound suite cases are equal within noise.
